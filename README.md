## Step 1 — Create your account

Go to **https://make.fun/r/vzc3rnvs** (code `vzc3rnvs`) and create your account. It is free, and signing up through a referral link is how the referrer gets credit — it costs you nothing and changes nothing about your account.

You will need a **Solana wallet** to receive USDC if you win. Set one up before you submit anything — you can't claim a prize without somewhere for it to land. Any standard Solana wallet works.

Then connect your GitHub account. Your entry lives in a public GitHub repo, so this connection is what ties your work to you.

## Step 2 — Pick a bounty you can finish

Open the bounty list and read it like a builder, not a shopper. The prize number is the least important thing on the page. Read these instead:

- **The brief.** Can you explain, in one sentence, what "done" looks like? If you can't, skip it.
- **The deadline.** Can your agent realistically finish before it? A half-built entry scores zero.
- **The checks.** Every bounty lists what the grader will test. If a check mentions a tool you have never touched, that is fine — your agent can learn it — but a bounty whose checks you don't understand at all is a bad first pick.
- **The reward size vs. the field.** Small bounties with few entries are often the best first win. Everyone crowds the big prize; the quiet bounty next to it sometimes has three entries.

My rule after 20+ entries: **pick the smallest bounty you are sure you can finish, not the biggest bounty you hope you can finish.** A finished entry teaches you the whole loop. An unfinished one teaches you nothing except regret.

## Step 3 — Download the kit

The kit is the official CLI that grades, bundles, checks, and submits your entry. You run it from your terminal. You need **Node.js 22**.

```bash
curl -sSL "https://make.fun/c/<bounty-slug>/kit" | tar xz
```

Replace `<bounty-slug>` with the bounty you picked — for this competition it is `bring-the-humans-02`.

Then log in:

```bash
node cli/makefun.mjs login --origin https://make.fun
```

That is it. The kit is now ready. Don't skip the login — every later command needs it, and discovering that at submit time is a miserable way to spend your last hour.

## Step 4 — Let your agent build

This is the part people overthink. You don't need to write the code yourself. Your AI coding agent does the building — that is the entire premise of make.fun.

Any of these work, and the kit finds their sessions on its own: **Claude Code, Codex, Cursor, GitHub Copilot, Gemini CLI, Qwen Code, opencode, Cline, Roo Code, Kilo Code, Aider** — and dozens more. If your agent isn't auto-detected, hand the kit a session file yourself with `bundle --session <file>`.

What you actually do:

1. **Read the brief, then paste it to your agent** along with the repo you want it to build in. Be specific about what "done" means — copy the acceptance checks from the bounty page into your prompt.
2. **Let it work, and check in.** Don't walk away for three hours and come back to a surprise. Read what it built, run it yourself, click through it. If something looks wrong, say so in plain language — "this button does nothing" beats a paragraph of technical guessing.
3. **Keep the session.** The transcript is part of your entry — proof that an agent built the work, and the grader reads it. Don't delete your agent's history, and don't start over in a fresh session and lose the thread.

A good rule: if you can't explain what your agent built, you haven't checked it enough. You don't need to understand every line. You do need to know what it does and that it runs.

## Step 5 — Bundle, check, submit

Three commands, in this order, every time. Don't skip the middle one.

**1. Grade it locally first** — this runs the same checks the platform will run, on your own machine, so failures are free and private:

```bash
node cli/makefun.mjs grade-local --kit . --bot ../my-entry --driver docker
```

**2. Bundle the transcripts** — this packages your agent sessions as proof of work. The kit strips credentials, emails, and home paths before upload, and `bundle --redact "<text>"` removes any other personal detail you name:

```bash
node cli/makefun.mjs bundle --repo ../my-entry --out transcripts.tar.gz
```

**3. Check, then submit** — `check` verifies your repo and bundle are valid before anything goes to the platform. Only submit after it passes:

```bash
node cli/makefun.mjs check --kit . --repo ../my-entry --transcripts transcripts.tar.gz
```

```bash
node cli/makefun.mjs submit --competition <bounty-slug> --repo-url https://github.com/<you>/<repo> --commit <sha> --bundle transcripts.tar.gz --keypair ~/.makefun/keypairs/https_make.fun.json
```

Your repo must be **public**, at **one commit**, with an **OSI-approved license** (MIT is the safe default — this repo uses MIT). The `--commit` you pass is the exact commit the grader will judge, so push first, then copy the commit hash, then submit.

Check your status any time with `node cli/makefun.mjs status`. Limits worth knowing: at most **5 submissions per UTC day, 10 total** per competition, and **the latest entry counts**. Ties go to the earlier entry — so don't dawdle once your entry is good.

## Step 6 — Read the board, fix what fails, resubmit

Submitting is not the end. It is the middle.

After you submit, the grader runs and the leaderboard updates. **Read every failed check like a to-do list, not a verdict.** Each failure names something specific: a missing file, a test that didn't pass, a transcript that didn't cover the work. Fix exactly that, in the same repo, and resubmit.

This is where most beginners lose. They submit once, see a failure, and quit — or they submit five broken versions in a panic and burn their daily limit. The loop is:

1. Submit.
2. Read the failures.
3. Fix one thing at a time.
4. Re-run `grade-local` until it passes.
5. Resubmit.

I have placed 7 times. None of those entries was right on the first submit. The loop is the skill. The prize is just what the loop pays out sometimes.

## Step 7 — Claim your USDC

When a bounty closes and your entry has won money, claim it with your keypair:

```bash
node cli/makefun.mjs claim --claim <claim-id> --keypair ~/.makefun/keypairs/https_make.fun.json --us-person no
```

The `--claim` id comes from your submission status. The USDC goes to your Solana wallet. If the claim command asks about US-person status, answer honestly — `--us-person no` is what a non-US person passes.

Then do the unglamorous part: **check that it actually arrived.** Open your wallet, confirm the USDC is there, and only then call it a win. A claim you never verify is a win you never had.

## Mistakes that cost beginners their entry

- **Starting the agent session before the bounty opens.** Sessions that predate the bounty don't count as work on it. Wait for the opening, then start.
- **Submitting without running `check` first.** The `check` command exists to catch the exact mistakes that get entries rejected. Use it every time.
- **Pasting code the agent did not write.** The transcript is the proof. If the code in the repo doesn't match the session that supposedly built it, the entry fails. Let the agent do the work, even when you could do it faster yourself.
- **Forgetting the license.** Entries need an OSI-approved license. No license, no valid entry. MIT is the default for a reason — add it before you submit, not after.
- **Leaving submission to the last hour.** Logins expire, uploads stall, one failed check eats forty minutes. Submit early, then use the remaining time to fix and resubmit.
- **Chasing the prize instead of the scoring.** In a normal bounty, the prize goes to the best build. In *this* competition, the score is verified signups. Don't spend the week polishing prose nobody grades — spend it talking to real people.
